C. ARQUITECTURA REAL RESULTANTE

Navegador HTML/CSS/JS → API Express → servicios → SQLite.
API Express → un agente Responses → get_learning_progress → servicio de lectura → SQLite.
Agente Responses → Web Search alojado → evidencia recuperada → JSON Schema → AJV → artefacto persistido.

Módulo nuevo: intención → interpretación → progreso real → búsqueda → módulo validado/guardado → fichas → quiz congelado → respuestas → score oficial → intento persistido → feedback → decisión humana.
Ruta: intención → interpretación → progreso/búsqueda → propuesta guardada → usuario elige → módulo. Proponer una ruta no crea intentos ni completitud.
Seed: módulo existente → quiz del banco adaptado → mismo scoring/persistencia; la falta de API key no impide guardar ese intento y se informa si falla feedback.

Se usa un solo agente con fases acotadas, sin LangChain/LangGraph ni múltiples agentes. Las fases no son agentes diferentes. Los cinco módulos iniciales no restringen los temas que se pueden solicitar.

E. BASE DE DATOS

users:
  user_id TEXT PK; created_at TEXT NOT NULL.

modules:
  module_id TEXT; version INTEGER >0; user_id TEXT nullable FK users;
  area TEXT; metric TEXT; content_json TEXT con json_valid;
  sources_json TEXT con json_valid; run_id TEXT nullable; created_at TEXT.
  PK(module_id, version). user_id null identifica contenido seed compartido.

quizzes:
  quiz_id TEXT PK; module_id TEXT; module_version INTEGER;
  user_id TEXT FK users; version INTEGER >0;
  quiz_json TEXT con json_valid; run_id TEXT nullable; created_at TEXT.
  FK(module_id,module_version) → modules.

attempts:
  attempt_id TEXT PK; user_id TEXT FK users; quiz_id TEXT FK quizzes;
  answers_json TEXT; results_json TEXT; ambos con json_valid;
  score INTEGER 0..100; correct_count INTEGER 0..5; created_at TEXT.
  UNIQUE(user_id,quiz_id).

agent_runs:
  run_id TEXT PK; user_id TEXT FK users; operation TEXT; model TEXT;
  prompt_version TEXT; input_json TEXT; tool_calls_json TEXT;
  output_json TEXT; JSON validado por SQLite; status TEXT; error TEXT nullable;
  created_at TEXT.

routes:
  route_id TEXT PK; user_id TEXT FK users; route_json TEXT con json_valid;
  run_id TEXT; created_at TEXT.

decisions:
  decision_id TEXT PK; user_id TEXT FK users; run_id TEXT FK agent_runs;
  decision TEXT restringido a accept/reject; created_at TEXT.

Hay índice de intentos por usuario/fecha. Foreign keys habilitadas y modo WAL.
Triggers rechazan UPDATE/DELETE de módulos, quizzes, intentos, rutas y decisiones. agent_runs permite finalizar un registro running una vez; un run terminal no se modifica ni elimina.

El quiz congelado contiene el orden exacto de preguntas/opciones y el índice correcto después de mezclar. results_json conserva el resultado por pregunta. Su unión con modules permite recuperar versión, contenido y fuentes.

Intentos, último score y mejor score son agregados derivados. El resumen legacy se mantiene bajo su clave anterior del navegador, sin convertirlo en supuestos intentos. Eliminar storage pierde la asociación local al UUID, no borra por sí mismo SQLite.

F. AGENTE

Modelo configurado: OPENAI_MODEL=gpt-5.6-luna, modificable por entorno. Se preservó el modelo solicitado. La documentación oficial consultada declara soporte de Web Search; no prueba acceso real de esta cuenta.

Prompts: system_prompt.md y user_prompt.md realmente leídos por el servidor. Incluyen Rol, Contexto, Tarea, Restricciones, Formato y Ejemplos. Cada run guarda textos y un hash SHA-256 de prompts/schemas para reconstrucción.

Schemas: los cinco archivos descritos. Salida final en sobre status/data/reason. status ok requiere datos válidos; insufficient_sources requiere data null y razón. Quiz exige cinco preguntas, cuatro opciones, índices 0..3, IDs distintos, enunciados distintos y opciones no duplicadas. Las referencias se contrastan con el módulo.

Herramienta de progreso: el modelo emite una function_call real cuando se usa el cliente real. El dispatcher valida nombre/argumentos y vincula user_id a la petición; solo consulta store.progress. No hay herramienta SQL ni de escritura. La integración fue ejercitada con dobles y SQLite real; la emisión por el modelo vivo está pendiente.

Búsqueda: Responses con herramienta web_search y elección requerida para módulos/rutas, antes de la etapa estructurada. Se conservan output items, fuentes y anotaciones. No se sustituye una búsqueda fallida con conocimiento interno.

Política de fuentes: prompt con niveles 1/2/3 aprobados. El código exige que las URLs finales hayan sido recuperadas y que exista alguna fuente clasificada 1 o 2. El modelo clasifica autoridad y justifica la elección; no hay un verificador automático de verdad semántica. Las preguntas nuevas se apoyan en módulos/fuentes persistidos. Los seeds sin fuentes están explícitamente señalados.

Límites: timeout de 60 segundos por petición, maxRetries=0 en SDK, un solo reintento de salida por error estructural, hasta tres tool calls de búsqueda en su fase. Rechazo, búsqueda fallida o insuficiencia de fuentes no activan loops automáticos. Una petición agéntica por UUID a la vez dentro del proceso.

Logs: solicitudes exactas copiadas antes de extender contexto, respuestas, outputs de herramientas, modelo, uso si la API lo reporta, artefactos y errores. Los errores conservan código/detalle disponible con redacción de patrones de claves. No se escriben headers de autorización en las trazas.

K. ELEMENTOS PENDIENTES Y LIMITACIONES

1. Configurar OPENAI_API_KEY en .env del servidor. Verificar acceso efectivo a gpt-5.6-luna.
2. Ejecutar smoke real de Responses, Web Search y function calling. Los tests con fixture no cubren comportamiento real del proveedor ni calidad del modelo.
3. Evaluar pedagógicamente módulos y quizzes generados: fuente trazable/JSON válido no garantiza verdad, pertinencia o clave correcta.
4. Ejecutar las tres corridas académicas en la fase prevista, exportar evidencia y revisar qué snapshots compartir.
5. Obtener definiciones oficiales L0–L4; etiqueta pendiente. El comportamiento de supervisión sí está implementado.
6. Completar análisis económico con usage real, precios aplicables y costo de herramientas. No hay costos medidos en esta misión.
7. UUID no es autenticación. Si se comparte como servicio público, revisar exposición y abuso antes de desplegar. La aplicación arranca en loopback y no se publicó.
8. Las claves de quiz llegan al navegador para el cálculo compartido: no es una evaluación protegida contra inspección de respuestas. El score persistido sí se calcula en servidor.
9. Historial y prompts crecen con el uso; no se implementó paginación/contexto resumido para gran escala. Mantener el alcance de esta etapa.
10. El banco seed tiene seis preguntas: el segundo quiz puede repetir cuatro. El contenido generado se comprueba por enunciado, no por equivalencia semántica automática.
11. Los triggers protegen de operaciones normales; alguien con acceso administrativo al archivo SQLite podría alterar su esquema. No se declara evidencia criptográficamente inviolable.
12. Borrar storage pierde la asociación local. No se añadió login ni recuperación de perfil.
